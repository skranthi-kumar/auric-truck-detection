## 5.1b oracle-box classifier (ConvNeXt-T in22k, 128 px crops, 2x box context, 15 ep fixed, seed 0) - 2026-10-09
- **Question:** if every object location were perfect, how much of the 5-class problem remains?
- **Setup:** src/oracle_cls.py; train on 7618 train GT crops, flips+rot90 aug, label smoothing 0.1, AdamW 2e-4 one-cycle; 8-way TTA; no val-based selection. M5 (MPS), 24 min.
- **Results:** val GT-crop accuracy 0.592, macro-recall 0.388. Oracle-box mAP50 (GT boxes, classifier probs as scores, evaluate.py) **0.429 (95% CI 0.347-0.532)**: Cargo 0.705, Box 0.568, Tractor 0.441, Flatbed 0.294, Liquid 0.136.
- Confusion: Cargo->Box 212, Box->Cargo 178, Flatbed->Cargo 60, Tractor->Cargo 49; Liquid 2/20 correct.
- Train loss reached 0.419 (~label-smoothing floor): near-perfect fit on train, 59% on val -> large generalisation gap.
- **Conclusion (provisional):** with localisation and detection removed, roughly half the mAP is still lost to classification. Whether classification is *the* binding constraint is not established (E1 class-agnostic AP50 is only 0.296, so detection is also far from target). Limits: one classifier/architecture (a lower bound on achievable accuracy), crops lose scene context, cannot separate ambiguity from label noise.
- **Competing explanations for the gap:** (A) train->val distribution shift vs (B) intrinsic ambiguity / label noise. **Discriminating test (running):** same classifier trained without the frozen 5.2 holdout (92 train images); A predicts holdout >> val accuracy, B predicts holdout ~ val.
- **A/B result (2026-10-09):** classifier trained without the 92 holdout train images: HOLDOUT (same distribution, 1396 crops) acc 0.634 / macro-recall 0.355 vs VAL acc 0.588 / macro-recall 0.372 (val confusion essentially unchanged).
- **Conclusion:** (A) train->val distribution shift **weakened** (same-distribution held-out images are no easier). The A/B test does NOT establish (B): train loss at the smoothing floor + ~63% on unseen same-distribution images is also a plain overfitting / too-little-data gap. **Open explanations:** (B1) label noise, (B2) genuine ambiguity at this resolution, (C) insufficient data / overfitting of this one classifier (single arch, 15 ep, 128 px, one seed). Tests: 5.3 learning curves (C), train-label cleaning E7 + blind audit (B1 vs B2).
- **Implication for target (revised 2026-10-09 cross-check):** 0.43 is what one classifier achieves with perfect boxes - a lower bound on achievable, not a ceiling. Classification is a large cost, but the claim "a bigger detector / longer schedule cannot help" is not supported and is withdrawn.
- **Crop-quality analysis (all 1552 val GT, experiments/results/oracle_cls_crop_quality.csv; sharpness = mean abs gradient inside GT box):**
  - 70% of the least-sharp quartile is labelled Truck w/Box (vs 15-22% in other quartiles); classifier predicts Box for 68% of least-sharp crops vs 18% of sharpest.
  - Within class: Box accuracy 0.80 (least sharp) vs 0.31-0.42 (sharper); Tractor 0.00 -> 0.72 with sharpness; Cargo flat/high (0.53-0.81).
  - Box share by brightness: 46% of darkest quartile vs 23% of brightest.
  - Visual (report/figs/oracle_cls_examples.png): confidently-correct Box crops are near-black, featureless boxes.
  - **Competing explanations:** (i) genuine appearance - flat uniform box roofs have low texture; (ii) Box labels concentrated on dark/barely visible objects, so the model learns "featureless -> Box" (an image-quality shortcut). Darkness pattern favours (ii) (white box roofs should be bright), but this is a correlation only; **unresolved** -> test with 5.2 confident-learning flags + blind audit of dark Box crops.

## 5.2 Training dynamics (E0_s0, 11 checkpoints epoch 0-45 + last; all 7618 train GT) - 2026-10-09
- **Method:** `cartography.py analyze` + `populations`. Per instance: p_true (best correct-class conf, IoU>=0.5), mean/std over checkpoints, forgetting (lower bound, sparse ckpts), AUM-style margin. Regions use quartile thresholds from the **inspected 80%** (6222 inst); the frozen holdout (92 images, 1396 inst) is untouched until the prediction test.
- **Per class (final learned):** Cargo 0.32, Box 0.67, Flatbed 0.32, Tractor 0.35, Liquid 0.04 (margin -0.18: Liquid is never learned, consistently predicted as Cargo/Box).
- **Populations (inspected):** easy 471 (median side 31 px), ambiguous 1556 (29 px, 55% crowded, 0.49 forget), medium 2639, **hard-missed 581 (13.7 px; 79% Cargo)**, **hard-confused 975 (21 px; another class consistently preferred)**.
  - hard-missed = resolution mechanism: smallest objects, no prediction at all.
  - hard-confused = confusable-pair / label-noise mechanism: Box->Cargo 169, Flatbed->Cargo 143, Cargo->Box 103, Tractor->Cargo 91, Liquid->Cargo 75 / ->Box 55. 89% of Liquid, 45% of Flatbed, 35% of Tractor fall here. Matches the 5.1b confusion pattern (independent model, GT crops).
  - Size gradient (inspected): learned 0.15 (<=16.5 px) -> 0.68 (>30 px).
- **Prediction test (holdout frozen on Day 1, scored once, no tuning):** logistic regression for "not learned at last ckpt", fit on inspected, scored on holdout: **AUC 0.725 metadata only (size, aspect, border, crowding, class); 0.815 + early dynamics (epochs 0-10); size alone 0.697.** Transfer to val (metadata model vs E0 correct-class recall): recall 0.64 (Q1 easy) -> 0.56 -> 0.57 -> 0.50 (Q4 hard), AUC 0.571.
- **Conclusion (provisional):** hardness is predictable on unseen images, mostly from object size + class; early dynamics add signal (+0.09 AUC). The transfer to val is weak (Q1 vs Q4: 0.64 vs 0.50; Q2 ~ Q3). Two populations: hard-missed (small; *consistent with* a resolution mechanism, but size is confounded with class - 79% Cargo) and hard-confused (same confusion pattern as 5.1). Label noise vs ambiguity vs too-little-data inside hard-confused is **unresolved** -> E7 + blind audit + 5.3.
- **Caveats:** E0 (640 px) only, single seed, single holdout split; "learned" threshold (0.25) and quartile region cut-offs are arbitrary choices; forgetting counts are lower bounds (sparse checkpoints).

## Learned context model (`src/context_model.py`, design declared before data collection) - 2026-10-10
- **Data:** E2_last sliced predictions on all 443 train images (Colab T4, 22 min): 99,470 class-agnostic objects, 91% background. Multinomial LR on 21 features (own class vector, size, aspect, R=150 px neighbour class histogram, neighbour count/conf, image class histogram); GBM as sensitivity.
- **Train 5-fold by image (incl. background): detector alone 0.940 -> context model 0.957.**
- **Val (applied once to ENS_E2 boxes): CTXM_lr 0.138 vs fixed-rule smoothing ENS_E2_ctx 0.139 -> delta -0.001 (CI -0.011 .. +0.010), P 0.42 -> REJECTED** (no better than the fixed rule). vs ENS_E2 without context: +0.009 (CI -0.001 .. +0.020), P 0.95 -> PROVISIONAL. Variants: p(c) without det weighting 0.131; GBM 0.095 / 0.094.
- **Why it does not beat the rule (mechanism, not tested further):** the model is fitted on detections the detector produced on its *own training images*, where its class scores are far more reliable than on unseen val images (train-set predictions are in-sample). The learned weights therefore trust the detector's own class vector more than they should on val; the more flexible GBM overfits this shift hardest (0.095). The clean fix is cross-fitted detections (k detectors, each predicting the images it did not train on), ~k x 2 GPU-h: out of budget.
- **Conclusion:** the fixed, declared smoothing rule stays in the pipeline. The context signal itself remains supported (H12); a learned version needs out-of-sample training detections. This is the designed "next experiment" for the report.

## 5.1c resolution test for the 0.43 oracle-box ceiling (DECLARED 11 Oct, before running; suggested by external review)

## RFX empirical head re-mapping (DECLARED + run 12 Oct; lever #1 from the RFX1/2-collapse review)
- **Motivation:** RFX0's head is a name-order guess (Cargo 11, Box 12, Flatbed 15, Tractor 13, Liquid 16).
